# Модели и сохранение данных

```text
Plant -> Zone -> Equipment -> Signal
                    |  |
                    |  +-> Asset (явный, необязательный)
                    +----> EquipmentType -> Asset (по умолчанию)
```

Asset не зависит от завода: code, name, glb_file, led_node_name, size_x/y/z,
updated_at. Файл необязателен; габариты положительные. EquipmentType содержит
code, name, default_asset и JSON-список шаблонов сигналов. Дата-миграция создаёт
тип oven, ассет oven с размерами 1.85×1.9×1.55 м и три шаблона:
state (state), power (number, кВт), temperature (number, °C).

Equipment: уникальный slug code, name, zone, обязательный type, необязательный
asset, pos_x/y/z, rotation_deg, уникальный nullable device_id, is_active,
created/updated. Пустой device_id нормализуется в NULL, поэтому допускается
несколько непривязанных станков. Изменение привязки — только админка.

Signal: equipment, key, name, unit, kind (state/number), device_key,
необязательные source/source_address. Уникальность по equipment/key.
При save Equipment в одной транзакции добавляются недостающие сигналы типа.
Повторный save сохраняет имена, device_key и настройки уже существующих сигналов.
При смене типа старые сигналы не удаляются, новые добавляются. bulk_create и
QuerySet.update обходят save; для создания станков используйте save/create или сервис.

EquipmentType проверяет структуру шаблонов, уникальность ключей и допустимые kind.
При отсутствии device_key сохраняется key. Удаление Equipment удаляет его сигналы;
удаление Asset снимает явную ссылку (после этого может сработать default_asset типа).
Удаление используемого типа или зоны блокируется PROTECT.

Миграции переименовывают поля Asset и Signal, не удаляя файлы или записи.
Старые kind/subtype и размеры Equipment, value_type/лимиты/таймаут/last_* Signal
сохранены в БД для недеструктивного перехода, скрыты из новой админки и не участвуют
в телеметрии. Последняя в этом этапе не реализована. min/max-валидация сохранена.
Размеры Equipment используются только для коробки при полном отсутствии ассета.
Старые типы сигналов, кроме state, преобразованы в number, остальные настройки сохранены.

До миграций рабочая SQLite сохранена в игнорируемой .qa/before-catalog-migration.sqlite3.
Проверка MigrationExecutor подтверждает сохранение координат, ссылок на GLB и настроек
сигналов при переходе с предыдущей схемы. Accounts и его маршруты не изменены.
