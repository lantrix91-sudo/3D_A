# Приложение на телефоне (PWA)

Plant Twin ставится на телефон как приложение: иконка на главном экране, запуск на
весь экран без адресной строки, работа **без сети**. Магазины приложений не нужны:
устанавливается прямо из браузера.

> **Осмотры теперь заполняются в отдельном Android-приложении «Обход»** — см.
> [mobile/README.md](../../mobile/README.md). Веб-версия (и PWA) показывает план, прогресс
> обхода и историю, но формы осмотра и офлайн-очереди в ней больше нет.

## Главное условие: HTTPS

Браузеры включают офлайн-режим (service worker) и установку **только по HTTPS**
или на `localhost`. По адресу вида `http://192.168.3.103:5173` приложение откроется
как обычный сайт, но без установки и без запуска без сети.

| Где открыт Plant Twin | Установка и офлайн |
| --- | --- |
| Railway (`https://….up.railway.app`) | Да, HTTPS уже есть. |
| Свой сервер с HTTPS-сертификатом | Да. |
| `http://192.168…` в сети цеха | Нет, см. «Локальная сеть цеха» ниже. |
| `npm run dev` (Vite) | Нет: service worker намеренно отключён при разработке. |

## Установка

**Android (Chrome):**
1. Откройте адрес Plant Twin и войдите.
2. В шапке появится зелёная кнопка **«Установить»**. Нажмите её. Если кнопки нет: меню ⋮ → «Добавить на главный экран» / «Установить приложение».
3. На экране появится иконка «Plant Twin». Долгое нажатие на иконку даёт ярлык «Обход».

**iPhone (Safari):**
1. Откройте адрес в **Safari** (в Chrome на iPhone установка не работает).
2. «Поделиться» → «На экран „Домой“» → «Добавить».

## Что работает без сети

Один раз войдите **со связью**. После этого:

- приложение открывается с иконки без сети, план и 3D-модели берутся из сохранённой копии, в шапке горит «Нет связи»;
- панель «Обход» показывает сохранённый маршрут и прогресс (только просмотр);
- при появлении связи приложение само обновляет вход и переподключает живые данные.

Без сети недоступны:
- карточка оборудования (паспорт, история, обходы);
- смена состояния из карточки;
- графики.

Эти данные запрашиваются каждый раз заново. Изменение состояния без сети можно
зафиксировать через осмотр в приложении «Обход»: неисправность из обхода меняет состояние после досылки.

Если связь «есть, но очень слабая», приложение ждёт сеть не больше 4 секунд и
показывает сохранённую копию, а свежие данные подтягивает в фоне.

## Обновление приложения

После новой сборки (`npm run build` и выкладка) телефон получает новую версию при
следующем открытии со связью. Версия меняется сама, по содержимому файлов. Если
приложение уже было открыто, новая версия включится после перезапуска.

## Выход и общий телефон

При выходе стираются сохранённые копии плана и маршрута, 3D-модели остаются.
Про неотправленные осмотры на общем телефоне — в [mobile/README.md](../../mobile/README.md).

## Ссылки и QR-коды

- `/#round` открывает панель обхода (тот же ярлык на иконке).
- `/#inspect=Owen-1` открывает станок `Owen-1` на плане (его карточку). Осмотр по QR-коду в приложении «Обход» — следующий шаг.

## Локальная сеть цеха

Если сервер стоит в цехе и Railway не используется, нужен HTTPS внутри сети. Варианты:

1. **Обратный прокси с внутренним сертификатом** (например, Caddy с `tls internal`):
   он раздаёт собранный `frontend/dist`, проксирует `/api`, `/ws`, `/media`, `/admin`
   и `/static` на Django. Корневой сертификат прокси нужно один раз установить на
   каждый телефон («Настройки → Безопасность → Установить сертификат»). Это решение
   для постоянной работы; его настройку мы пока не проверяли.
2. **Только для проверки на одном телефоне.** В Chrome на Android откройте
   `chrome://flags/#unsafely-treat-insecure-origin-as-secure`, впишите
   `http://192.168.3.103:<порт>` и перезапустите Chrome. Адрес должен вести на
   **собранное** приложение (`npm run build` и `npm run preview -- --host`), а не на
   `npm run dev`.

## Временный показ через cloudflared quick tunnel

Quick tunnel даёт публичный HTTPS-адрес `https://<случайные-слова>.trycloudflare.com`
без настройки DNS и сертификатов. Vite (`server`/`preview.allowedHosts`) и Django
при `DEBUG=true` (`ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`) уже разрешают эти адреса.
`/api`, `/ws`, `/media` и `/admin` идут через прокси Vite на Django `127.0.0.1:8000`.

**Просто показать (без офлайна):**

```powershell
# backend: python manage.py runserver (DEBUG=true)
# frontend: npm run dev
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:5173
```

Откройте на телефоне адрес из вывода cloudflared. В режиме `npm run dev` service
worker отключён намеренно, поэтому установки и офлайна нет.

**Проверить установку и работу без сети:**

```powershell
cd frontend
npm run build          # после каждого изменения кода
npm run preview        # собранное приложение на :4173, тот же прокси на Django
& "C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url http://localhost:4173
```

1. Откройте адрес туннеля на телефоне (Android: Chrome, iPhone: Safari) и войдите.
2. Установите приложение: кнопка «Установить» в шапке или меню браузера (см. «Установка» выше).
3. Откройте приложение с иконки, затем включите **режим полёта** и закройте/откройте
   приложение снова. Должен открыться план с 3D-моделями и плашкой «Нет связи», панель
   обхода показывает сохранённый маршрут.
4. Выключите режим полёта: плашка гаснет.

Ограничения quick tunnel:

- **Адрес меняется при каждом запуске** cloudflared. Для браузера это другой сайт:
  установленное приложение, вход и офлайн-кэш привязаны к старому адресу, после
  перезапуска туннеля их нужно делать заново. Для постоянного адреса нужен
  именованный туннель с вашим доменом или Railway.
- **Адрес публичный.** Его может открыть любой, кто его знает, включая `/admin/`.
  При `DEBUG=true` ошибки показывают трассировку и фрагменты настроек. Не держите
  туннель открытым дольше показа, используйте стойкие пароли, а после показа
  остановите cloudflared (Ctrl+C).
- Через туннель работает ваша локальная база и `media`: всё, что сделают на телефоне,
  попадёт в них.

## Как устроено (для разработчиков)

| Файл | Назначение |
| --- | --- |
| `frontend/public/manifest.webmanifest`, `public/icons/` | Название, цвета, иконки (обычная и maskable для Android, apple-touch для iOS), ярлык «Обход». |
| `frontend/src/pwa/sw.js` | Шаблон service worker. Стратегии: оболочка приложения из кэша (файлы с хэшем в имени); навигация и `GET /api/v1/plan/`, `/rounds/today/`, `/assets/` — сначала сеть, при отсутствии сети или таймауте 4 с — сохранённая копия; `.glb` — из кэша (ключ без query, чтобы подписанные ссылки S3/R2 не дублировались). POST-запросы не перехватываются. |
| `frontend/vite.config.js` | Плагин сборки: генерирует `dist/sw.js` со списком файлов и версией по их содержимому. |
| `frontend/src/pwa/register.js` | Регистрация SW (только в production и в защищённом контексте), кнопка «Установить», очистка данных при выходе. |
| `frontend/nginx.conf.template` | `sw.js` и манифест отдаются с `no-cache`, иначе телефон не увидит обновление. |

Запуск без сети: `api.restoreSession()` при ошибке сети возвращает `'offline'` вместо
`false`. Приложение открывается из кэша, сохранённый refresh-токен не стирается, а
WebSocket и запросы сами обновляют access-токен, когда связь появится.
