# «Обход» — приложение для ежедневного обхода (Android APK и PWA)

Отдельное приложение для инженеров в цеху: выбрать маршрут, пройти станки по шагам,
заполнить чек-лист, сфотографировать, сохранить. Работает **без сети**: осмотры копятся
на телефоне и уходят на сервер, когда связь появится. 3D-плана здесь нет, он остаётся
в веб-версии (`frontend/`).

Экраны: **Настройки сервера → Вход → Маршруты → Шаги → Осмотр → Станок (история)**.

Один и тот же код собирается двумя способами:

| | APK (Capacitor) | PWA (сайт с экрана «Домой») |
| --- | --- | --- |
| Телефоны | Android | iPhone (Safari) и Android (Chrome) |
| Где интерфейс | внутри APK | https://mobile-…up.railway.app, сохраняется service worker |
| Сервер | любой, в том числе `http://` в сети цеха | только `https://` (облачный backend) |
| Камера | `@capacitor/camera` | `<input type="file" capture>` |
| Установка | файл APK | «Поделиться → На экран «Домой»» / «Установить приложение» |

Раздел про PWA — [ниже](#pwa-iphone-и-android-без-apk).

## Как это устроено (простыми словами)

- `mobile/` — обычный веб-проект на Vite (HTML + CSS + JavaScript), как `frontend/`, только без three.js.
- **Capacitor** берёт собранную папку `dist/` и кладёт её **внутрь APK**. На телефоне приложение —
  это окно встроенного браузера Android (WebView), которое открывает файлы из APK. Поэтому
  интерфейс открывается без сети: он не скачивается с сервера.
- За данными (маршруты, отправка осмотров) приложение ходит на backend по адресу из
  экрана «Настройки», например `http://192.168.3.103:8000`.
- Возможности телефона (камера, кнопка «Назад») подключаются плагинами Capacitor:
  `@capacitor/camera` и `@capacitor/app`.

```text
mobile/
├── package.json          # свои зависимости: Vite, Capacitor; без three.js
├── capacitor.config.json # имя «Обход», id приложения, схема http (см. ниже)
├── vite.config.js        # npm run dev: порт 5174, прокси на Django
├── index.html            # + манифест и apple-* теги для установки на «Домой»
├── Dockerfile, nginx.conf.template, railway.json  # PWA в Railway (сервис mobile)
├── public/icon.svg       # иконка (экран входа)
├── public/manifest.webmanifest, public/icons/      # PWA: название, иконки 192/512, apple-touch-icon
├── resources/icon.svg    # исходник иконки Android
├── src/
│   ├── main.js           # навигация между экранами, загрузка данных, очередь
│   ├── api/client.js     # запросы к API и JWT (перенесено из frontend)
│   ├── api/server.js     # адрес сервера: хранение, проверка связи /health/
│   ├── offline/queue.js  # офлайн-очередь осмотров в IndexedDB (перенесено из frontend)
│   ├── offline/photos.js # сжатие фото в браузере (перенесено из frontend)
│   ├── offline/drafts.js # черновик незаконченного осмотра
│   ├── offline/images.js # картинки станков на телефоне (IndexedDB), чтобы были видны без сети
│   ├── rounds/logic.js   # прогресс, выбор маршрута (перенесено из frontend)
│   ├── rounds/stepFlow.js # кнопки формы: Далее / Сохранить и завершить / ← Назад / Пропустить
│   ├── camera.js         # камера и галерея
│   ├── pwa/sw.js         # service worker PWA: оболочка без сети (шаблон, версию подставляет сборка)
│   ├── pwa/register.js   # регистрация SW только в веб-сборке по HTTPS
│   ├── screens/          # settings, login, routes, steps, inspection, equipment
│   └── style.css
└── android/              # проект Android Studio (создан командой npx cap add android)
```

## Что нужно на компьютере

1. **Node.js 22 или новее** (`node -v`). Capacitor 8 на более старом не работает.
2. **Android Studio** (свежая версия) — https://developer.android.com/studio.
   В ней уже есть Java (JDK) и Android SDK, ставить отдельно не нужно. При первом запуске
   согласитесь на установку SDK по умолчанию.

## Установка на телефон

**Вариант 1 — по USB (удобно при разработке).**

1. На телефоне: *Настройки → О телефоне* → 7 раз нажать «Номер сборки» — включится режим разработчика.
2. *Настройки → Для разработчиков* → включить **Отладка по USB**.
3. Подключить телефон кабелем, на телефоне разрешить отладку для этого компьютера.
4. В Android Studio вверху выбрать телефон в списке устройств и нажать зелёный **▶ Run**.
   Приложение поставится и запустится.

**Вариант 2 — файлом.**

1. Скопируйте `app-debug.apk` на телефон (кабель, Telegram, Google Drive).
2. Откройте файл на телефоне. Android попросит разрешить установку из этого источника
   (браузера, Telegram, «Файлов») — разрешите.
3. Нажмите «Установить». На экране появится иконка **«Обход»**.

> **Важно про обновления.** Debug APK подписан ключом того компьютера, где собран
> (`%USERPROFILE%\.android\debug.keystore`). Новая версия ставится **поверх** старой без
> потери данных, только если собрана на том же компьютере. Иначе Android потребует удалить
> приложение — а вместе с ним удалятся **неотправленные осмотры**. Перед переустановкой
> убедитесь, что на экране «Все осмотры отправлены».

## Адрес сервера

При первом запуске открывается экран **«Настройки»**: поле «Адрес backend»
(по умолчанию `http://192.168.3.103:8000`), кнопки **«Проверить связь»** и **«Сохранить»**.
Адрес хранится на телефоне; поменять его можно кнопкой ⚙ на экране маршрутов или
«Изменить» на экране входа. Смена адреса завершает вход и стирает сохранённые копии
маршрутов (неотправленные осмотры остаются и уйдут на новый адрес).

«Проверить связь» делает `GET /health/`. Если не получается:

1. Телефон и компьютер в **одной Wi-Fi сети**.
2. Django запущен **на всех интерфейсах**, а не только на localhost:
   ```powershell
   cd E:\3D_project\plant-twin\backend
   .\.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8000
   ```
3. В `backend/.env`: `DEBUG=true` и `LOCAL_IP=192.168.3.103` (IP компьютера; узнать — `ipconfig`).
4. Порт 8000 открыт в брандмауэре Windows (PowerShell от администратора, один раз):
   ```powershell
   New-NetFirewallRule -DisplayName "Plant Twin Django 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private
   ```
5. Проверка с телефона в обычном браузере: `http://192.168.3.103:8000/health/` → `{"status": "ok"}`.

## Что включено для http в локальной сети и зачем

Backend в цеху работает по **http** (без сертификата). Android и встроенный браузер
по умолчанию такое блокируют, поэтому включено три вещи:

| Где | Что | Зачем |
| --- | --- | --- |
| `capacitor.config.json` | `"server": { "androidScheme": "http" }` | Интерфейс внутри APK открывается как `http://localhost` (по умолчанию было бы `https://localhost`). Страница с https не может обращаться к http-серверу — это «смешанное содержимое» (mixed content), WebView его режет. Когда и страница, и сервер на http, смешивания нет. |
| `android/app/src/main/res/xml/network_security_config.xml` + ссылка на него в `AndroidManifest.xml` | `cleartextTrafficPermitted="true"` | С Android 9 приложениям запрещён незашифрованный http («cleartext»). Разрешаем, потому что адрес сервера вводится на телефоне и заранее неизвестен. |
| `capacitor.config.json` | `"android": { "allowMixedContent": false }` | Смешанное содержимое **не** разрешаем: оно не нужно, раз страница тоже на http. Записано явно, чтобы было видно, что это решение, а не забытая настройка. |
| `backend/config/settings.py` | origins `http://localhost`, `https://localhost`, `capacitor://localhost` в CORS при `DEBUG=true` | Страница (`http://localhost`) и API (`http://192.168.3.103:8000`) — разные адреса. Браузер пропускает ответ, только если backend разрешил этот origin (CORS). Для production `http://localhost` добавляется в `CORS_ALLOWED_ORIGINS` вручную ([DEPLOYMENT.md](../docs/DEPLOYMENT.md)). |

Цена http: в общей Wi-Fi сети пароль и токены можно перехватить. Для цеховой сети это
допустимо на время пилота; когда появится backend по `https://`, достаточно указать
его адрес в «Настройках» (и при желании выключить cleartext).

> Не меняйте `androidScheme` у уже установленного приложения: сменится адрес страницы,
> и телефон «забудет» вход, маршруты и **неотправленные осмотры** (они привязаны к адресу).

## Камера

Выбран плагин **`@capacitor/camera`**, а не `<input type="file" capture>`:

- Фото уменьшается до 1600 px и поворачивается **самим Android**. В WebView пришлось бы
  загружать в память снимок 12–50 Мп целиком — на простых телефонах это медленно и
  может закончиться нехваткой памяти.
- Если Android выгрузил приложение, пока открыта камера (частая история на телефонах
  с малой памятью), плагин отдаёт снимок после перезапуска (событие `appRestoredResult`).
  Приложение заранее сохраняет черновик осмотра и после перезапуска открывает ту же
  форму с уже заполненными ответами и новым фото. У `<input>` снимок в этом случае просто теряется.
- Понятные ошибки и отмена: закрыли камеру — ничего не происходит.

Кнопки в форме: **«📷 Сфотографировать»** (камера) и **«Из галереи»** (до 5 фото).
Разрешение на камеру не требуется: плагин открывает системное приложение «Камера».
В браузере и в PWA вместо плагина работает `<input type="file" capture>` (см. раздел PWA).

## Ориентация

Только портрет: `android:screenOrientation="portrait"` у `MainActivity` в
`android/app/src/main/AndroidManifest.xml`.

## Как работает без сети

1. **Интерфейс** лежит в APK — открывается всегда.
2. **Вход** нужен один раз со связью. Refresh-токен хранится на телефоне; без сети
   приложение открывается с сохранёнными данными, токен обновится, когда появится сеть.
3. **Маршруты и маршрут дня** сохраняются на телефоне после каждой загрузки. Без сети
   показывается сохранённая копия («без сети»). История станка — тоже, если её открывали со связью.
4. **Осмотр** при сохранении записывается в IndexedDB телефона вместе с фото и сразу
   считается сделанным (строка «⏳ ждёт отправки»). Очередь отправляет осмотры сама:
   сразу, при появлении сети, при возвращении в приложение, при запуске и раз в 30 с.
   Повторная отправка безопасна: у каждого осмотра свой `client_id`, сервер дубль не создаёт.
5. **Черновик**: всё, что введено в форму, сразу сохраняется. Закрыли приложение посреди
   осмотра — при следующем запуске откроется тот же станок с заполненной формой.
6. **Картинки станков** (миниатюры в шагах и крупно в форме) после загрузки маршрута
   копируются в IndexedDB — по одной на станок. Без сети показывается копия. Ссылки на
   bucket подписаны и меняются, поэтому копия сравнивается по адресу файла без подписи.
   «Сделать фото станка» (engineer и admin) работает только со связью: фото сразу уходит на сервер.
7. Отклонённый сервером осмотр (например, станок удалили) помечается «отклонено» —
   его можно удалить кнопкой «Удалить неотправленный осмотр».

Подробно (ответы сервера, часовой пояс, срок 48 часов) — в [docs/ROUNDS.md](../docs/ROUNDS.md).

На **общем телефоне** перед «Выйти» дождитесь «Все осмотры отправлены»: неотправленные
осмотры уйдут от имени того, кто войдёт следующим (приложение предупредит).

## PWA: iPhone и Android без APK

Та же сборка `dist/`, выложенная как сайт (сервис **mobile** в Railway, см.
[DEPLOYMENT.md](../docs/DEPLOYMENT.md)). Адрес: https://mobile-production-7c69.up.railway.app.

**Установка на телефон:**

- **iPhone:** открыть адрес в **Safari** (не в Chrome и не во встроенном браузере мессенджера) →
  кнопка «Поделиться» → **«На экран «Домой»»** → «Добавить».
- **Android:** открыть в Chrome → меню ⋮ → **«Установить приложение»** (или «Добавить на гл. экран»).

Иконка «Обход» появится рядом с другими приложениями; открывается без адресной строки.

**Что из чего сделано:**

| Файл | Зачем |
| --- | --- |
| `public/manifest.webmanifest` | Название «Plant Twin — Обход» / «Обход», `start_url: /`, `display: standalone` (без адресной строки), портрет, иконки 192/512 и maskable |
| `index.html` | `apple-mobile-web-app-capable`, `-title`, `-status-bar-style` и `apple-touch-icon` — iPhone читает их вместо манифеста |
| `src/pwa/sw.js` | Service worker: при первом открытии сохраняет все файлы интерфейса; без сети отдаёт их из кэша. Данные он не кэширует — маршрут и история и так лежат в localStorage, осмотры в IndexedDB |
| `vite.config.js` | При `npm run build` собирает `dist/sw.js` со списком файлов и версией. Новая сборка → новая версия → телефон обновится при следующем открытии со связью |
| `nginx.conf.template` | `sw.js` и манифест — `Cache-Control: no-cache` (иначе обновление не дойдёт), любой путь → `index.html` |

**Адрес сервера.** При сборке задаётся `VITE_API_URL` (в Railway — переменная сервиса mobile).
Экран «Настройки» подставляет его по умолчанию, вводить ничего не нужно. Порядок:
сохранённый на телефоне адрес → `VITE_API_URL` → `http://192.168.3.103:8000`.
PWA открыта по `https://`, поэтому сервер тоже только `https://`: браузер не пустит запрос к
`http://` (mixed content). «Проверить связь» об этом предупредит.

**Особенности iPhone:**

- Камера — `<input type="file" accept="image/*" capture="environment">`: Safari сразу
  открывает заднюю камеру. Фото сжимается до 1600 px в браузере (`offline/photos.js`).
  Окно камеры открывается сразу по нажатию: Safari не откроет его после паузы.
- Неотправленные осмотры хранятся в IndexedDB. Safari может стереть данные **сайта**, который не
  открывали 7 дней, но не установленного на «Домой» приложения — поэтому ставьте на «Домой».
  Приложение также просит браузер не очищать хранилище (`navigator.storage.persist()`).
- Кнопки «Назад» на iPhone нет — используйте ← в шапке. На Android системная «Назад»
  возвращает на предыдущий экран приложения.
- Service worker работает только по HTTPS (или на `localhost`); по `http://192.168…` PWA
  открывается как обычный сайт, без работы без сети.

**Обновление:** собрать и выложить заново (`railway up`, см. DEPLOYMENT). Телефон
подхватит новую версию при следующем открытии со связью (иногда — со второго открытия).

## Иконка и название

- PWA: иконки в `public/icons/` (192, 512, maskable-512, apple-touch-icon 180) — нарисованы
  из того же `resources/icon.svg`; название — `public/manifest.webmanifest` и `apple-mobile-web-app-title`.
- Название «Обход» — `appName` в `capacitor.config.json` и
  `android/app/src/main/res/values/strings.xml`.
- Иконка — `android/app/src/main/res/mipmap-*` (обычная, круглая и слои адаптивной иконки),
  цвет фона адаптивной иконки — `values/ic_launcher_background.xml`, заставка — `drawable*/splash.png`.
  Исходник — `resources/icon.svg`. Заменить: Android Studio → правый клик по `res` →
  **New → Image Asset**.
